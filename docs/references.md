# Technical references

These are implementation references, not a bibliography for literary judgments.
Consult the current versions when changing integration behavior.

- GitHub: [Custom workflows with Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
- GitHub: [Configuring a Pages publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
- GitHub: [Creating an Issue, including URL parameters](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue).
- Pandoc: [User's guide](https://pandoc.org/MANUAL.html), especially Markdown, HTML, sandboxing and EPUB output.
- W3C: [Web Annotation Data Model](https://www.w3.org/TR/annotation-model/), especially quote/context selectors. Our v1 report is not a claim of standards conformance.
- W3C: [EPUBCheck](https://www.w3.org/publishing/epubcheck/), technical publication validation.

Project-specific precedents supplied by the owner:

- [yomi-corpus](https://github.com/hiroshi-manabe/yomi-corpus): local drafts, immutable review evidence, submission receipts and separation of processing/review state.
- [nippo-jisho](https://github.com/hiroshi-manabe/nippo-jisho): source/interpretation boundaries, factual correction history and Issue-based feedback.

This scaffold does not copy their implementation or their task segmentation. Its
feedback model is intentionally looser than corrective transcription or readings.
