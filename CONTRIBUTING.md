# Contributing

You can contribute by **reading and noticing things**. You need not be a translator,
propose a replacement sentence, use Git, or finish a chapter. Casual but specific
observations are welcome. This is currently a solo project; the maintainer may be
both its reader-reviewer and its editor. There is no expectation of recruiting a team.

Read the [short editorial policy](docs/editorial-policy.md). Use the contributor
workbench for the revision you are reading. Mark a phrase, sentence, paragraph or
longer passage, add a comment, and keep reading. A chapter-level comment is also
possible. Keep your notes in the language in which you can express them best.

Examples: “Was this name spelled differently earlier?”, “This sounds far too
formal for the speaker”, “Would this sentence be clearer as two?”, “I don't
understand what is happening here.” Uncertainty is useful information; expertise
is not a prerequisite for reporting your reading experience.

The workbench stores notes locally, supports more than one note across chapters,
and exports a report. Copy it into a GitHub Issue, or attach the downloaded JSON
when it is large. Opening GitHub is **not** submitting an Issue. See the
[contributor workflow](docs/contributor-workflow.md) for the exact sequence.
The schema-v2 workbench also supports book titles, division/section headings and
bibliographic credits. Saved comments appear as compact margin notes; overlapping
selections and notes across several sections are permitted.

Your report cites an immutable revision. A later translation may have entirely
different sentences. That does not make your report invalid: the maintainer and
AI decide whether the underlying observation still matters. A report is not an
instruction that must be applied mechanically, and it is not a claim that the
whole work has been reviewed.

## Code and documentation

Small focused changes are easiest to inspect. Read AGENTS.md and the relevant
design document. Describe behavior and tests, not just file edits. Do not change
archive records, public pointers, licensing or publication settings as an
incidental consequence of a UI change. New abstractions should solve an observed
problem; this is not intended to become a general translation-management platform.

Use the pull-request template. The maintainer decides what to merge and publish.
There is no guaranteed response time or obligation to accept a literary suggestion.

## Rights and privacy

Report your own observations. Do not paste passages from copyrighted third-party
translations as proposed replacements without a suitable basis. GitHub Issues
and the deployed review site are public in the intended setup. Do not include
private email, credentials, personal information or confidential manuscripts.

Project licensing is not yet selected; see RIGHTS.md. Do not assume a contributor
license agreement or invent one on behalf of the maintainer.
